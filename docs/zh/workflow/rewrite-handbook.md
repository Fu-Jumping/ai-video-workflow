# 源层重写操作手册

"整体重写"指推翻既有方向（结构锚点、人物组合、镜头组划分等），从 Step 1 开始重做。本手册说明工具提供什么支持、需要人工做什么。

> 工具能力边界：`clean-view` / `rebuild-view` 只管理 Obsidian 观看层投影，**不清理或备份源 Step 文件**。源层的旧版本只能靠 git 兜底。

## 一、重写前

1. **打标签/备份**：`git tag scene-<n>-complete` 或直接提交，保证旧版本可回退。
2. **明确重写范围**：哪些是"结构性重做"（锚点、序列、组划分、编号、防混淆判据），哪些是"可复用迁移"（独立镜头的内容、角色细节、关键帧文案）。
3. **记录重写决策**：在 Step 0 创作简报或项目 README 的变更日志里写清"为什么推翻、新方向是什么"。

## 二、重写执行顺序

1. **Step 1 故事内核**：重写结构锚点、资产清单、视觉工程基线——这是下游的总开关。
2. **Step 2 世界设定**：按新序列重建角色/场景段落（保留可复用的细节，重排编号）。
3. **Step 3 分镜**：重构镜头组目录（删除旧组、新建新组）、重排镜头编号、重写镜头组说明与受影响镜头卡。
4. **Step 4/5**：删除/重排对应关键帧与视频提示词文件，按新编号重生成。
5. **Step 6 执行计划**：重新生成。
6. **Step 0**（若启用）：把重写决策补进研究文件，新增来源卡按需处理。

## 三、Obsidian 观看层

- `clean-view --dry-run` 先预览要清理的投影文件；`clean-view` 只删生成文件、保留用户笔记（`04_个人笔记/`）。
- **增量导出不会删除旧编号的投影**：镜头编号重排后，旧编号投影会以 `orphaned` 形式留在 vault，必须先 `clean-view`（或 `rebuild-view`）再导出。
- `rebuild-view` 按 sync → clean → export → verify-obsidian 四步重建；如果项目含多个研究来源卡，旧版本曾因来源卡投影同名冲突在此处失败（已修复，如仍失败请先跑 `export-obsidian` + `verify-obsidian` 确认）。
- 重写不改 `.codex/` 运行镜像（除非改了母包 pack）；`rebuild-view` 会先自动 sync IDE runtime。

## 四、重写后验收

1. 全量 `verify` 通过（Step 0~6 合同）。
2. `export-obsidian` + `verify-obsidian` 通过，观看层无旧编号残留。
3. 按[影响面排查手册](./impact-analysis.md)复查语义判据（母题口径、色彩纪律、防混淆判据）。
4. 提交新状态并更新变更日志。

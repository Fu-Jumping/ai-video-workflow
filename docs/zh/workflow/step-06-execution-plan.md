## 引用其它步骤文件的写法

- 推荐使用反引号相对路径文本，例如 `` `../04_图片提示词/镜头组-001/镜头-001-关键帧-01.md` ``，不进入 Markdown 链接解析，最稳。
- 若使用 Markdown 链接，目标必须相对**引用文件自身所在目录**可解析（例如 `06_执行计划/00_执行计划.md` 引用 Step 4 应写 `../04_图片提示词/...`）；`verify` 会检查相对链接目标是否存在（`broken-relative-link`）。注意 Obsidian 观看层会按 vault 内路径重新解析链接，同一链接在源层合法也可能在投影层报坏链，因此跨步骤引用优先用反引号路径。

## 粗剪交付（roughcut）

粗剪交付由 CLI 的 `roughcut` 命令族完成，把已选用的素材按顺序交给剪映继续剪，不改写创作正文：

- `roughcut plan --project <项目路径>`：从内容树与素材记录生成或刷新本目录下的 `00_粗剪顺序表.md`；「成片顺序」列允许手改，`--check` 只校验不写入。顺序与选用在表内定稿，即算粗剪确认完成。
- `roughcut pack --project <项目路径> --out <导出目录>`：按顺序表导出只读素材包——按成片顺序编号的分段目录加一份顶层清单（逐项写来源镜头/分镜、文件版本、对白/字幕、缺项、检查状态）；只复制不移动，绝不覆盖项目原件。
- `roughcut draft --project <项目路径> [--name <草稿名>]`：程序直接生成剪映 11.6 原生草稿（全新编号、离线加密、注册前备份草稿索引）。安全护栏：剪映运行中（含托盘进程）拒绝写入；`videoeditor.dll` 指纹校验，版本不符明确报错；目标草稿目录已存在拒绝覆盖。生成后必须打开剪映人工核对。

约束与口径：顺序表与将来桌面 App 的排序不共用记录；素材包是顺序定稿那一刻的独立快照，之后换选用不回写；粗剪产物一律按「未定稿材料」对待，第七步（发布物料）不读取、不检查它们。剪映升级后指纹不匹配时，按 `apps/cli/vendor/README.md` 重新适配。
